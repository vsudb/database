# Таблица синонимов терминов баз данных

В данной таблице приведено сопоставление терминов баз данных на различных уровнях абстракции: от концептуального проектирования до разговорной терминологии.

---

## Сводная таблица терминов и синонимов

| Концептуальный уровень (ER-модель) | Реляционная теория (Математика) | Физический уровень (SQL / СУБД) | Упрощенный / Разговорный термин |
| :--- | :--- | :--- | :--- |
| **Сущность** *(Entity)* | **Отношение** *(Relation)* | **Таблица** *(Table)* | Файл данных, Набор данных |
| **Экземпляр сущности** *(Entity Instance)* | **Кортеж** *(Tuple)* | **Строка / Запись** *(Row / Record)* | Элемент таблицы, Объект |
| **Атрибут** *(Attribute)* | **Атрибут** *(Attribute)* | **Столбец / Поле** *(Column / Field)* | Свойство, Характеристика |
| **Домен** *(Domain)* | **Домен** *(Domain)* | **Тип данных / Ограничение** *(Data Type / Constraint)* | Множество допустимых значений |
| **Связь** *(Relationship)* | **Внешний ключ / Отображение** | **Внешний ключ** *(Foreign Key / FK)* | Связка, Ссылка |
| **Ключевой атрибут** *(Key Attribute)* | **Первичный ключ** *(Primary Key)* | **Первичный ключ** *(Primary Key / PK)* | Уникальный код, ID |
| **Ассоциативная / Связующая сущность** *(Associative Entity)* | **Декартово произведение / Составное отношение** | **Связывающая / Промежуточная таблица** *(Junction / Bridge / Pivot Table)* | Смычка, Таблица-перемычка, Таблица связи |

---

## Краткие пояснения уровней

* **Концептуальный уровень (ER-модель):** Уровень проектирования и описания предметной области без привязки к конкретным техническим реализациям.
* **Реляционная теория:** Строгий математический аппарат (реляционная алгебра), лежащий в основе реляционных баз данных.
* **Физический уровень (SQL / СУБД):** Терминология, используемая при непосредственной работе с реляционными СУБД (PostgreSQL, MySQL, Oracle и др.) и написании SQL-запросов.
* **Упрощенный / Разговорный термин:** Термины, используемые в неформальном общении разработчиков и пользователей.

---

## Особенности связующих сущностей (Many-to-Many)

Связь **Многие-ко-Многим ($M:N$)** не может быть напрямую реализована в реляционной СУБД только с помощью первичных и внешних ключей исходных таблиц. Для её реализации происходит разбиение связи $M:N$ на две связи **Один-ко-Многим ($1:N$)** через промежуточную сущность:

1. **На концептуальном уровне:** **Ассоциативная сущность** *(Associative Entity)* — объект, хранящий информацию о связи двух других объектов (например, *«Зачисление»* между сущностями *«Студент»* и *«Курс»*).
2. **На физическом уровне (в СУБД):** **Связывающая таблица** *(Junction Table / Bridge Table / Pivot Table / Join Table)* — таблица, содержащая как минимум два внешних ключа (FK), ссылающихся на первичные ключи (PK) связываемых таблиц.
