# Трёхзначная логика (3VL) и NULL в SQL

В SQL используется **трёхзначная логика (Three-Valued Logic, 3VL)**. В отличие от стандартной булевой логики с двумя состояниями (`TRUE` и `FALSE`), SQL вводит третье состояние — **`UNKNOWN`** (неизвестно). Это состояние возникает при работе с неопределенными значениями — **`NULL`**.

## 1. Таблицы истинности для 3VL

Для вычисления логических выражений с участием `UNKNOWN` применяются следующие правила.



## Полная таблица истинности

| A | B | A AND B | A OR B | A XOR B | NOT A |
| :---: | :---: | :---: | :---: | :---: | :---: |
| `TRUE` | `TRUE` | **`TRUE`** | **`TRUE`** | **`FALSE`** | **`FALSE`** |
| `TRUE` | `FALSE` | **`FALSE`** | **`TRUE`** | **`TRUE`** | **`FALSE`** |
| `FALSE` | `FALSE` | **`FALSE`** | **`FALSE`** | **`FALSE`** | **`TRUE`** |
| `FALSE` | `UNKNOWN` | **`FALSE`** | **`UNKNOWN`** | **`UNKNOWN`** | **`TRUE`** |
| `TRUE` | `UNKNOWN` | **`UNKNOWN`** | **`TRUE`** | **`UNKNOWN`** | **`FALSE`** |
| `UNKNOWN` | `UNKNOWN` | **`UNKNOWN`** | **`UNKNOWN`** | **`UNKNOWN`** | **`UNKNOWN`** |

##

| :---: | :---: | :---: |
| `FALSE` | `UNKNOWN` | 🔴 **`  FALSE`** |
| `TRUE` | `UNKNOWN`  | 🟡 **`UNKNOWN`** |

| A | B | A OR B |
| :---: |:---: | :---: |
| `FALSE` | `UNKNOWN` | 🟡 **`UNKNOWN`** |
| `TRUE` | `UNKNOWN`  | 🟢 **`TRUE   `** | 

## Основные правила запоминания:

* **`AND` (Логическое И):** Достаточно хотя бы одного `FALSE`, чтобы весь результат стал `FALSE` (даже если второе значение `UNKNOWN`).
* **`OR` (Логическое ИЛИ):** Достаточно хотя бы одного `TRUE`, чтобы весь результат стал `TRUE` (независимо от наличия `UNKNOWN`).
* **`XOR` (Исключающее ИЛИ):** С участием `UNKNOWN` результат почти всегда равен `UNKNOWN`, так как для точного сравнения необходимо знать оба значения.
* **`NOT` (Логическое НЕ):** Инвертирует известное значение (`TRUE` в `FALSE` и наоборот), а для `UNKNOWN` возвращает `UNKNOWN`.


## 2. Фильтрация и сравнения

### Поведение `WHERE`

Предложение `WHERE` оставляет только те строки, для которых выражение оценивается строго в **`TRUE`**.
Строки со значениями **`FALSE`** и **`UNKNOWN`** отсеиваются.

### Сравнения с `NULL`

Любое прямое сравнение с `NULL` с помощью стандартных операторов (`=`, `<>`, `>`, `<`) даёт `UNKNOWN`.

```sql
-- Вернет 0 строк, так как выражение 'age = NULL' вычисляется в UNKNOWN
SELECT * FROM users WHERE age = NULL; 

-- Правильный вариант:
SELECT * FROM users WHERE age IS NULL;
```

## 3. Ловушки операторов подзапросов

### 1. Оператор `NOT IN` (Главная ловушка)

Выражение `x NOT IN (1, 2, NULL)` разворачивается в:

```sql
(x <> 1) AND (x <> 2) AND (x <> NULL)
```

Поскольку `x <> NULL` даёт `UNKNOWN`, цепочка `AND UNKNOWN` превращает всё выражение в `UNKNOWN` (или `FALSE`).

> **Результат:** Если подзапрос внутри `NOT IN` вернёт хотя бы один `NULL`, итоговый запрос вернёт **пустой результат**.

### 2. Оператор `EXISTS` и `NOT EXISTS` (Безопасный вариант)

Определяет только одно — вернул ли подзапрос **хотя бы одну строку**.

* Выражение с `EXISTS` возвращает строго **`TRUE`** или **`FALSE`**.
* `EXISTS` никогда не возвращает `UNKNOWN`.

```sql
-- Абсолютно корректный запрос (SELECT NULL проверит факт наличия строки, а не ее содержание)
SELECT * FROM clients c
WHERE EXISTS (
    SELECT NULL FROM orders o WHERE o.client_id = c.id
);
```

> **Совет:** Используйте `NOT EXISTS` вместо `NOT IN` для защиты от `NULL`.

### 3. Оператор `ANY` / `SOME`

Оператор `ANY` разворачивается через логическую цепочку **`OR`**:

```sql
x = ANY (1, 2, NULL)  -->  (x = 1) OR (x = 2) OR (x = NULL)
```

* Если найдено совпадение (например `x = 1`), выражение вернёт `TRUE` (так как `TRUE OR UNKNOWN = TRUE`).
* Если совпадений нет, результат будет `UNKNOWN`.

### 4. Оператор `ALL` (Коварная ловушка)

Оператор `ALL` разворачивается через логическую цепочку **`AND`**:

```sql
x > ALL (10, 20, NULL)  -->  (x > 10) AND (x > 20) AND (x > NULL)
```

* Потенциальный баг: Наличие одного `NULL` в результатах подзапроса ломает всю проверку `ALL`, превращая результат в `UNKNOWN` для каждой строки (`TRUE AND UNKNOWN = UNKNOWN`).

### 5. Поведение `ALL` и `ANY` с пустым множеством

Если подзапрос возвращает **0 строк**:

| Выражение | Результат | Причина |
| ----- | ----- | ----- |
| `x > ALL (пустой подзапрос)` | **`TRUE`** | Нет элементов, нарушающих условие. |
| `x > ANY (пустой подзапрос)` | **`FALSE`** | Нет ни одного элемента, удовлетворяющего условию. |
