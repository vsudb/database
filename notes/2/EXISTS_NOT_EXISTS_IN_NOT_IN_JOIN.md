# Лекция: `EXISTS`, `NOT EXISTS`, `IN`, `NOT IN`, `NULL` и отличие от `JOIN`

## 1. Схема таблиц для примеров

В примерах используются таблицы учебной базы данных:

```text
STUDENT
- STUDENT_ID   — идентификатор студента
- SURNAME      — фамилия
- NAME         — имя
- UNIV_ID      — идентификатор университета
- CITY         — город проживания
- STIPEND      — стипендия

UNIVERSITY
- UNIV_ID      — идентификатор университета
- UNIV_NAME    — название университета
- CITY         — город университета
- RATING       — рейтинг

EXAM_MARKS
- STUDENT_ID   — идентификатор студента
- SUBJ_ID      — идентификатор предмета
- MARK         — оценка

SUBJECT
- SUBJ_ID      — идентификатор предмета
- SUBJ_NAME    — название предмета
```

Основная идея всех рассматриваемых конструкций — проверить связь между таблицами или наличие значения в другом наборе данных.

---

## 2. Оператор `EXISTS`

`EXISTS` проверяет, возвращает ли вложенный запрос хотя бы одну строку.

Общий вид:

```sql
SELECT столбцы
FROM внешняя_таблица AS В
WHERE EXISTS (
    SELECT *
    FROM внутренняя_таблица AS ВТ
    WHERE условие_связи
);
```

Если подзапрос возвращает хотя бы одну строку, условие `EXISTS` считается истинным для текущей строки внешнего запроса.

### Пример

Получить студентов, у которых есть хотя бы одна неудовлетворительная оценка:

```sql
SELECT s.STUDENT_ID, s.SURNAME, s.NAME
FROM STUDENT AS s
WHERE EXISTS (
    SELECT *
    FROM EXAM_MARKS AS em
    WHERE em.STUDENT_ID = s.STUDENT_ID
      AND em.MARK < 3
);
```

Для каждого студента проверяется наличие хотя бы одной строки в `EXAM_MARKS`, где оценка меньше 3.

Если у студента пять неудовлетворительных оценок, он всё равно попадёт в результат один раз. `EXISTS` проверяет сам факт существования, а не количество найденных строк.

### Важная особенность

Внутри `EXISTS` можно использовать `SELECT *`, `SELECT 1` или любой другой список выражений:

```sql
WHERE EXISTS (SELECT * FROM EXAM_MARKS ...)
```

```sql
WHERE EXISTS (SELECT 1 FROM EXAM_MARKS ...)
```

Для результата это обычно одно и то же: важен факт наличия строки, а не содержимое `SELECT`.

---

## 3. Оператор `NOT EXISTS`

`NOT EXISTS` проверяет, что вложенный запрос не возвращает ни одной строки.

### Пример

Получить университеты, в которых не учится ни один студент:

```sql
SELECT u.UNIV_ID, u.UNIV_NAME
FROM UNIVERSITY AS u
WHERE NOT EXISTS (
    SELECT *
    FROM STUDENT AS s
    WHERE s.UNIV_ID = u.UNIV_ID
);
```

Для каждого университета проверяется отсутствие студентов с таким же `UNIV_ID`.

### Пример: студенты без неудовлетворительных оценок

```sql
SELECT s.STUDENT_ID, s.SURNAME, s.NAME
FROM STUDENT AS s
WHERE NOT EXISTS (
    SELECT *
    FROM EXAM_MARKS AS em
    WHERE em.STUDENT_ID = s.STUDENT_ID
      AND em.MARK < 3
);
```

Этот запрос означает: «у студента не существует ни одной неудовлетворительной оценки».

### Важное отличие от формулировки «только отличные оценки»

Запрос выше включит также студентов, у которых вообще нет оценок. Ведь у них действительно не существует неудовлетворительных оценок.

Если нужны только студенты, у которых есть оценки и все они отличные, нужны две проверки:

```sql
SELECT s.STUDENT_ID, s.SURNAME, s.NAME
FROM STUDENT AS s
WHERE EXISTS (
    SELECT *
    FROM EXAM_MARKS AS em
    WHERE em.STUDENT_ID = s.STUDENT_ID
)
AND NOT EXISTS (
    SELECT *
    FROM EXAM_MARKS AS em
    WHERE em.STUDENT_ID = s.STUDENT_ID
      AND em.MARK <> 5
);
```

Первая часть требует наличие хотя бы одной оценки, вторая запрещает любые оценки, отличные от 5.

## 4. Оператор `IN`

`IN` проверяет, входит ли значение в набор значений.

### Список конкретных значений

```sql
SELECT *
FROM STUDENT
WHERE KURS IN (1, 2, 3);
```

Результат содержит студентов первого, второго и третьего курсов.

То же условие можно записать через `OR`:

```sql
SELECT *
FROM STUDENT
WHERE KURS = 1
   OR KURS = 2
   OR KURS = 3;
```

`IN` обычно короче и лучше показывает смысл условия.

### `IN` с подзапросом

Получить студентов, которые учатся в университетах Воронежа:

```sql
SELECT *
FROM STUDENT
WHERE UNIV_ID IN (
    SELECT UNIV_ID
    FROM UNIVERSITY
    WHERE CITY = 'Воронеж'
);
```

Внутренний запрос формирует набор идентификаторов университетов, а внешний запрос оставляет студентов, чьи `UNIV_ID` входят в этот набор.

### `IN` и повторения

Если подзапрос вернёт один и тот же `UNIV_ID` несколько раз, внешняя строка всё равно не будет продублирована. `IN` проверяет принадлежность набору, а не выполняет обычное соединение строк.

## 5. Оператор `NOT IN`

`NOT IN` проверяет, что значение не входит в набор.

### Пример без подзапроса

```sql
SELECT *
FROM STUDENT
WHERE KURS NOT IN (1, 2);
```

Выбираются студенты третьего, четвёртого и других курсов, если такие значения есть.

### Пример с подзапросом

Получить студентов, которые не учатся в университетах Воронежа:

```sql
SELECT *
FROM STUDENT
WHERE UNIV_ID NOT IN (
    SELECT UNIV_ID
    FROM UNIVERSITY
    WHERE CITY = 'Воронеж'
);
```

На первый взгляд это аналогично `NOT EXISTS`, но при наличии `NULL` поведение может существенно отличаться.

## 6. Трёхзначная логика SQL

В обычной логике есть два результата: `TRUE` и `FALSE`. В SQL есть три результата:

- `TRUE` — истинно;
- `FALSE` — ложно;
- `UNKNOWN` — неизвестно.

`UNKNOWN` появляется прежде всего при сравнении с `NULL`.

### Что такое `NULL`

`NULL` — это не ноль, не пустая строка и не обычное значение. Он означает отсутствие или неизвестность значения.

Поэтому такие условия не дают `TRUE`:

```sql
NULL = 5
```

```sql
NULL <> 5
```

```sql
NULL = NULL
```

Результат этих сравнений — `UNKNOWN`.

В предложении `WHERE` проходят только строки, для которых условие равно `TRUE`. Строки с результатом `FALSE` или `UNKNOWN` отбрасываются.

### Правильная проверка `NULL`

Нельзя проверять `NULL` через `=` или `<>`:

```sql
-- Неправильно
WHERE CITY = NULL

-- Неправильно
WHERE CITY <> NULL
```

Используйте специальные операторы:

```sql
WHERE CITY IS NULL
```

```sql
WHERE CITY IS NOT NULL
```

## 7. Почему `NOT IN` опасен при наличии `NULL`

Рассмотрим таблицу `UNIVERSITY`:

| UNIV_ID |
|---:|
| 1 |
| 2 |
| `NULL` |

Запрос:

```sql
SELECT *
FROM STUDENT
WHERE UNIV_ID NOT IN (
    SELECT UNIV_ID
    FROM UNIVERSITY
);
```

Логически SQL проверяет примерно следующее:

```text
student.UNIV_ID <> 1
AND student.UNIV_ID <> 2
AND student.UNIV_ID <> NULL
```

Последнее сравнение даёт `UNKNOWN`. Всё выражение через `AND` также становится `UNKNOWN`, поэтому строка не проходит `WHERE`.

В результате `NOT IN` может вернуть пустой результат или исключить строки неожиданным образом, если подзапрос способен вернуть `NULL`.

### Как обезопасить `NOT IN`

Можно убрать `NULL` из подзапроса:

```sql
SELECT *
FROM STUDENT
WHERE UNIV_ID NOT IN (
    SELECT UNIV_ID
    FROM UNIVERSITY
    WHERE UNIV_ID IS NOT NULL
);
```

Но для отрицательной проверки чаще безопаснее и понятнее использовать `NOT EXISTS`:

```sql
SELECT s.*
FROM STUDENT AS s
WHERE NOT EXISTS (
    SELECT *
    FROM UNIVERSITY AS u
    WHERE u.UNIV_ID = s.UNIV_ID
);
```

`NOT EXISTS` проверяет строки по условию связи и не ломается из-за постороннего `NULL` в наборе.

### Важное уточнение

Если само значение `s.UNIV_ID` равно `NULL`, условие:

```sql
u.UNIV_ID = s.UNIV_ID
```

не будет истинным. Поэтому такой студент может попасть в результат `NOT EXISTS`: для него не нашлось совпадения. Если это нежелательно, добавьте явное условие:

```sql
WHERE s.UNIV_ID IS NOT NULL
AND NOT EXISTS (...)
```

## 8. Сравнение `IN` и `EXISTS`

Эти конструкции часто решают одну и ту же задачу, но выражают её по-разному.

### Через `IN`

```sql
SELECT *
FROM STUDENT
WHERE UNIV_ID IN (
    SELECT UNIV_ID
    FROM UNIVERSITY
    WHERE CITY = 'Воронеж'
);
```

Смысл: `STUDENT.UNIV_ID` входит в набор идентификаторов университетов Воронежа.

### Через `EXISTS`

```sql
SELECT s.*
FROM STUDENT AS s
WHERE EXISTS (
    SELECT *
    FROM UNIVERSITY AS u
    WHERE u.UNIV_ID = s.UNIV_ID
      AND u.CITY = 'Воронеж'
);
```

Смысл: для данного студента существует университет с таким же идентификатором и городом Воронеж.

### Практическое правило

- `IN` удобно использовать, когда подзапрос формирует простой набор значений.
- `EXISTS` удобно использовать, когда нужно проверить наличие связанной строки или применить несколько условий к ней.
- Для отрицательной проверки при возможном `NULL` обычно предпочтительнее `NOT EXISTS`, а не `NOT IN`.

Современные СУБД могут оптимизировать эти варианты одинаково, поэтому выбор часто зависит от ясности запроса и свойств данных.

## 9. Что такое `JOIN`

`JOIN` объединяет строки из двух или более таблиц в один результирующий набор.

### Пример `INNER JOIN`

Получить студентов и названия их университетов:

```sql
SELECT s.SURNAME, s.NAME, u.UNIV_NAME
FROM STUDENT AS s
JOIN UNIVERSITY AS u
  ON u.UNIV_ID = s.UNIV_ID;
```

Здесь результат содержит поля сразу из двух таблиц: `STUDENT` и `UNIVERSITY`.

### `JOIN` для фильтрации

Получить студентов из Воронежа:

```sql
SELECT s.*
FROM STUDENT AS s
JOIN UNIVERSITY AS u
  ON u.UNIV_ID = s.UNIV_ID
WHERE u.CITY = 'Воронеж';
```

Это может быть эквивалентно варианту с `IN` или `EXISTS`, если связь корректная и в `UNIVERSITY.UNIV_ID` нет дубликатов.

## 10. Главное отличие `EXISTS` от `JOIN`

### `EXISTS` отвечает на вопрос «есть ли связанная строка?»

```sql
SELECT s.*
FROM STUDENT AS s
WHERE EXISTS (
    SELECT *
    FROM EXAM_MARKS AS em
    WHERE em.STUDENT_ID = s.STUDENT_ID
      AND em.MARK < 3
);
```

Студент выводится один раз независимо от количества неудовлетворительных оценок.

### `JOIN` фактически соединяет строки

```sql
SELECT s.*
FROM STUDENT AS s
JOIN EXAM_MARKS AS em
  ON em.STUDENT_ID = s.STUDENT_ID
WHERE em.MARK < 3;
```

Если у студента три неудовлетворительные оценки, он может появиться три раза — по одной строке на каждое совпадение.

Чтобы убрать повторы, понадобится `DISTINCT`:

```sql
SELECT DISTINCT s.*
FROM STUDENT AS s
JOIN EXAM_MARKS AS em
  ON em.STUDENT_ID = s.STUDENT_ID
WHERE em.MARK < 3;
```

### Сравнение

| Задача | Предпочтительная конструкция |
|---|---|
| Проверить наличие связанной записи | `EXISTS` |
| Проверить отсутствие связанной записи | `NOT EXISTS` |
| Получить поля из обеих таблиц | `JOIN` |
| Посчитать связанные записи | `JOIN` + `GROUP BY` или коррелированный подзапрос |
| Не допустить повторения внешних строк | `EXISTS` или `JOIN` + `DISTINCT` |
| Проверить принадлежность простому набору | `IN` |

## 11. `LEFT JOIN` и `NOT EXISTS`

`LEFT JOIN` часто используют для поиска строк без соответствия.

### Вариант через `NOT EXISTS`

Найти университеты без студентов:

```sql
SELECT u.*
FROM UNIVERSITY AS u
WHERE NOT EXISTS (
    SELECT *
    FROM STUDENT AS s
    WHERE s.UNIV_ID = u.UNIV_ID
);
```

### Эквивалентный вариант через `LEFT JOIN`

```sql
SELECT u.*
FROM UNIVERSITY AS u
LEFT JOIN STUDENT AS s
  ON s.UNIV_ID = u.UNIV_ID
WHERE s.STUDENT_ID IS NULL;
```

`LEFT JOIN` сохраняет все строки левой таблицы, а для отсутствующих совпадений подставляет `NULL`. Поэтому проверка `s.STUDENT_ID IS NULL` оставляет университеты без студентов.

### Важное правило для `LEFT JOIN`

Условия, относящиеся к правой таблице, могут менять смысл запроса в зависимости от места их размещения.

Неудачный вариант:

```sql
SELECT u.*
FROM UNIVERSITY AS u
LEFT JOIN STUDENT AS s
  ON s.UNIV_ID = u.UNIV_ID
WHERE s.KURS = 1;
```

Условие `WHERE s.KURS = 1` отбрасывает строки с `NULL`, поэтому `LEFT JOIN` фактически начинает работать как `INNER JOIN`.

Если условие должно участвовать в соединении, его можно перенести в `ON`:

```sql
SELECT u.*
FROM UNIVERSITY AS u
LEFT JOIN STUDENT AS s
  ON s.UNIV_ID = u.UNIV_ID
 AND s.KURS = 1;
```

## 12. `EXISTS` и `JOIN`: полусоединение

По смыслу `EXISTS` часто называют **полусоединением** (`semi-join`): внешняя таблица фильтруется по наличию совпадения, но строки внутренней таблицы не добавляются в результат.

Для запроса:

```sql
SELECT s.*
FROM STUDENT AS s
WHERE EXISTS (
    SELECT *
    FROM EXAM_MARKS AS em
    WHERE em.STUDENT_ID = s.STUDENT_ID
);
```

результат содержит только столбцы `STUDENT`, а `EXAM_MARKS` используется как условие отбора.

Обычный `JOIN` — это полноценное соединение. Он может:

- добавлять столбцы второй таблицы;
- увеличивать количество строк из-за нескольких совпадений;
- требовать `DISTINCT`, если нужны уникальные строки внешней таблицы.

## 13. Типичные ошибки

### Ошибка 1. Сравнение с `NULL` через `=`

```sql
WHERE CITY = NULL
```

Правильно:

```sql
WHERE CITY IS NULL
```

### Ошибка 2. Безопасное на вид `NOT IN` с потенциальным `NULL`

```sql
WHERE UNIV_ID NOT IN (SELECT UNIV_ID FROM UNIVERSITY)
```

Если подзапрос вернёт `NULL`, результат может оказаться неожиданным. Предпочтительно:

```sql
WHERE NOT EXISTS (
    SELECT *
    FROM UNIVERSITY AS u
    WHERE u.UNIV_ID = s.UNIV_ID
)
```

### Ошибка 3. Дубликаты после `JOIN`

```sql
SELECT s.*
FROM STUDENT AS s
JOIN EXAM_MARKS AS em
  ON em.STUDENT_ID = s.STUDENT_ID;
```

Студент может повториться для каждой оценки. Если нужно только проверить наличие оценок, лучше использовать `EXISTS`.

### Ошибка 4. Неправильная корреляция

```sql
WHERE STUDENT_ID = STUDENT_ID
```

Такое условие может сравнивать столбец сам с собой и не связывать внутренний запрос с внешним. Надёжнее использовать псевдонимы:

```sql
WHERE em.STUDENT_ID = s.STUDENT_ID
```

### Ошибка 5. Отсутствие проверки наличия оценок

```sql
WHERE NOT EXISTS (
    SELECT *
    FROM EXAM_MARKS AS em
    WHERE em.STUDENT_ID = s.STUDENT_ID
      AND em.MARK <> 5
)
```

Этот запрос выбирает и студентов без оценок. Для условия «есть оценки и все они равны 5» нужна дополнительная проверка `EXISTS`.

## 14. Как выбрать конструкцию: алгоритм

### Нужно вывести данные только из одной таблицы

Спросите себя: «Мне нужно проверить наличие связанной строки?»

- Да, есть совпадение → `EXISTS`.
- Нет совпадений → `NOT EXISTS`.
- Нужно проверить вхождение в список → `IN`.
- Нужно проверить невхождение → `NOT IN`, но только после проверки на `NULL`; чаще лучше `NOT EXISTS`.

### Нужно вывести данные из обеих таблиц

Используйте `JOIN`:

```sql
SELECT s.SURNAME, u.UNIV_NAME
FROM STUDENT AS s
JOIN UNIVERSITY AS u
  ON u.UNIV_ID = s.UNIV_ID;
```

### Нужно найти строки без пары

Используйте один из двух вариантов:

```sql
WHERE NOT EXISTS (...)
```

или:

```sql
LEFT JOIN ... WHERE правая_таблица.ключ IS NULL
```

`NOT EXISTS` обычно легче читать как проверку отсутствия, особенно при сложных условиях.

## 15. Итоговая памятка

```text
EXISTS      — существует хотя бы одна подходящая строка.
NOT EXISTS  — не существует ни одной подходящей строки.
IN          — значение входит в набор.
NOT IN      — значение не входит в набор, но NULL может изменить результат.
IS NULL     — значение отсутствует.
IS NOT NULL — значение присутствует.
JOIN        — объединяет строки таблиц и может создавать повторы.
LEFT JOIN   — сохраняет все строки левой таблицы.
```

### Самые важные правила

1. Для проверки наличия связанной записи используйте `EXISTS`.
2. Для проверки отсутствия связанной записи обычно используйте `NOT EXISTS`.
3. `NOT IN` опасен, если подзапрос может вернуть `NULL`.
4. `NULL` проверяют только через `IS NULL` и `IS NOT NULL`.
5. `JOIN` может продублировать строку внешней таблицы, если есть несколько совпадений.
6. Если нужны поля только внешней таблицы и проверка наличия связи, `EXISTS` часто лучше `JOIN`.
7. Для «есть оценки и все оценки отличные» нужны одновременно `EXISTS` и `NOT EXISTS`.
