# Как читать план запроса (кратко для студентов)

## 1. Как получить план

```sql
EXPLAIN          -- только оценка
EXPLAIN ANALYZE  -- реальный план + время выполнения
SELECT ...;
```

## 2. Как читать

- Читай **снизу вверх** (от листьев к корню).
- Каждый узел — это операция.
- Стрелки показывают поток данных.

## 3. Сканирование таблиц

| Тип сканирования     | Что делает                                                                 | Когда хорошо                  | Когда плохо          |
|----------------------|----------------------------------------------------------------------------|-------------------------------|----------------------|
| **Seq Scan**         | Читает всю таблицу целиком                                                 | Маленькая таблица             | Большая таблица      |
| **Index Scan**       | Идёт по индексу + читает строки таблицы                                    | Мало строк, хороший индекс    | Индекс неселективный |
| **Index Only Scan**  | Берёт всё только из индекса                                                | Covering-индекс               | —                    |
| **Bitmap Heap Scan** | Сначала строит битовую карту по индексу, потом читает нужные страницы таблицы по порядку | Среднее/большое количество строк | —                 |

**Bitmap Heap Scan** — компромисс между Index Scan и Seq Scan.  
PostgreSQL использует его, когда по индексу находится уже довольно много строк (сотни–тысячи), и прыгать по таблице становится невыгодно.

## 4. Типы соединений (JOIN)

| Тип соединения  | Как работает                                      | Сложность (примерно)                                      | Когда эффективен                     | Когда опасен                   |
|-----------------|---------------------------------------------------|-----------------------------------------------------------|--------------------------------------|--------------------------------|
| **Nested Loop** | Для каждой строки внешней таблицы ищет во внутренней | O(N × M) без индекса<br>O(N × log M) с индексом          | Маленькие таблицы + хороший индекс   | Большие таблицы без индексов   |
| **Hash Join**   | Строит хеш-таблицу по одной таблице               | O(N + M)                                                  | Средние/большие таблицы              | Мало памяти / плохая оценка    |
| **Merge Join**  | Обе таблицы должны быть отсортированы             | O(N log N + M log M) — если нужна сортировка<br>O(N + M) — если уже отсортированы | Большие отсортированные данные | Дорогая сортировка             |

**Важное уточнение про Merge Join:**  
Ему не обязательно нужны индексы. Нужны **отсортированные данные**. Сортировка может прийти:
- из индекса (Index Scan),
- из явной операции `Sort`,
- из предыдущего Merge Join.

## 5. Как подсказать СУБД, какой JOIN использовать

В PostgreSQL нет прямых хинтов вида `/*+ USE_HASH_JOIN */`, но можно временно отключать ненужные алгоритмы:

```sql
-- Только Hash Join
SET enable_nestloop = off;
SET enable_mergejoin = off;
SET enable_hashjoin = on;

-- Только Nested Loop
SET enable_hashjoin = off;
SET enable_mergejoin = off;
SET enable_nestloop = on;

-- Только Merge Join
SET enable_hashjoin = off;
SET enable_nestloop = off;
SET enable_mergejoin = on;
```

После эксперимента обязательно верни настройки:

```sql
RESET enable_nestloop;
RESET enable_hashjoin;
RESET enable_mergejoin;
```

Можно ограничить действие одной транзакцией:

```sql
BEGIN;
SET LOCAL enable_nestloop = off;
SET LOCAL enable_mergejoin = off;
EXPLAIN ANALYZE SELECT ...;
ROLLBACK;
```

## 6. Типы индексов

| Тип индекса | Для чего подходит                                      | Особенности                            | Когда использовать              |
|-------------|--------------------------------------------------------|----------------------------------------|---------------------------------|
| **B-tree**  | Равенство, диапазоны (`=`, `<`, `>`, `BETWEEN`, `ORDER BY`) | Самый распространённый (по умолчанию) | Почти всегда в первую очередь   |
| **Hash**    | Только равенство (`=`)                                 | Быстрее на точное совпадение           | Редко                           |
| **GIN**     | Массивы, JSONB, полнотекстовый поиск                   | Хорош для «содержит»                   | `@>`, `?`, массивы, полнотекст  |
| **GiST**    | Геоданные, диапазоны, похожий поиск                    | Универсальный для сложных типов        | PostGIS, диапазоны              |
| **BRIN**    | Очень большие таблицы с упорядоченными данными         | Очень маленький                        | Логи, временные ряды            |

## 7. Селективность индекса

**Селективность** — насколько сильно индекс умеет отсекать ненужные строки.

- **Высокая селективность** (хороший индекс) — оставляет мало строк.  
  Пример: `student_id`, `email`, `passport_number`.

- **Низкая селективность** (плохой индекс) — почти ничего не отсекает.  
  Пример: `kurs` (1–4), `gender` (2 значения).

**Правило:**
- Селективный индекс → PostgreSQL чаще выбирает **Index Scan**.
- Неселективный индекс → чаще будет **Bitmap Heap Scan** или **Seq Scan**.

## 8. На что смотреть в первую очередь

| Что смотреть            | Хорошо             | Плохо                   |
|-------------------------|--------------------|-------------------------|
| Seq Scan                | Маленькая таблица  | Большая таблица         |
| Index / Index Only Scan | Есть нужный индекс | —                       |
| Nested Loop             | Маленькие данные + индексы | Большие таблицы   |
| cost / actual time      | Низкие             | Высокие                 |
| rows vs actual rows     | Примерно совпадают | Сильно отличаются       |

## 9. Главные красные флаги

- Seq Scan по большой таблице
- Nested Loop + Seq Scan
- Большая разница между оценкой `rows` и реальным количеством
- Дорогая сортировка больших объёмов
- Высокий `actual time` на узле

**Главное правило:** ищи самые дорогие узлы снизу плана — именно они обычно тормозят запрос.
